# ADR-0002：模型事实源 —— BPMN XML（bpmn-moddle 模型树）

- 状态：Accepted
- 日期：2026-09-14

## 背景

双模式统一的前提是选定唯一事实源。候选三选：自研 JSON DSL / BPMN XML / 双模型 + 转换器。
本条决策同时回答"XML 底座怎么建"：XML 解析/序列化（元素顺序、命名空间声明、`bpmndi` 布局、扩展属性注入、任意第三方 XML 的往返保真）是全项目风险最高、测试矩阵最大的轮子，bpmn.io 的 `bpmn-moddle` 在该层苦耕十年。

## 决策

1. **BPMN XML 为唯一事实源**：内核操作一棵 moddle 模型树；钉钉式视图与 Vue-Flow 画布只是它的两种投影；导出即序列化；
2. **XML 模型层复用 MIT 的 `bpmn-moddle`/`moddle`，不重造**；画布、属性面板、交互层全部自研（Vue 3 + Vue-Flow）。
   这正是 bpmn-js 自身的架构分层（画布与模型分离）——"原生重写"重写的是交互体验层，不是 XML 保真层，不丢人且绕开最高风险轮子；
3. **诚实条款**：保证"设计器画出的内容无损导出为合法 BPMN"；不承诺"任意第三方 BPMN 文件所有细节无损导入"。但 XML 为源使导入成为一等能力——超出 v1 元素集的内容以只读方式保留，不静默丢弃。

## 被否决的备选

- **自研 JSON DSL 为源**：双模式统一可行，但项目本质变成"DSL 设计 + BPMN 编译器"，DSL 无社区共识、编译器测试矩阵巨大，且失去任意标准 BPMN 文件可导入的生态兼容故事；
- **双模型 + 转换器**：两套维护、转换必有损、不一致 bug 温床（wflow 转 BPMN 即此模式的痛点样本）。

## 后果

- **最高优先级测试不变量**：`parse(xml) → model → compile()` 往返语义等价（ROADMAP Step 1 测试链 2）；
- 对 `bpmn-moddle` 的依赖面小（MIT、独立于画布），升级可控；
- 钉钉式视图的设计自由度受 BPMN 表达力约束（细化见 ADR-0004）。
