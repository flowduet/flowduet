# ADR-0012：组件默认配色跟随宿主，新适配显式启用

- 状态：Accepted（用户通过 Q11 澄清后的问题卡片确认行为决策；具体 API 待规格审阅，不构成产品实施授权）。
- 日期：2026-11-03。
- 来源：[R2 品牌批准记录](../design/system-v1/brand/2026-11-02-decisions.md#用户批准)、[首批适配范围](../design/system-v1/brand/2026-11-03-first-adaptation-scope.md)。

FlowDuet 作为嵌入式组件库，品牌层沿用“一树两冠”与双色标识；组件层的新适配默认跟随宿主，品牌预设由宿主显式选择。首批新适配也须显式启用，未启用的旧调用保持原有外观和行为，避免将设计基线的批准变成所有集成方的自动视觉升级。这里的“默认跟随宿主”指启用新适配后的配色默认，不表示已有调用已具有新能力。

长期以同一套视觉语义分别适配各 UI 库的主题机制：跟随宿主时读取其已有主题，品牌预设时将品牌规则映射到库的主题入口，具体映射与弹层机制按库分别验证。首批只有 Element Plus 路线，其他框架保持后续方向，不因此获得接入授权。

## 取舍与后果

相比升级后强制启用，显式启用增加旧、新两条路径的验证与维护成本，但让现有集成方自行安排升级。相比所有组件默认带品牌色，默认跟随宿主优先保证嵌入一致性，FlowDuet 风格由结构、空间、状态语义与节点类型表达；品牌展示仍可明确使用品牌预设。

外观配置属于实例呈现，不进入 BPMN XML 或表单业务 rules/options；既有显式表单配置优先，新适配只补默认值。不能为主题改写既有内容，也不能污染其他实例或无关宿主控件。显式配置引起的视觉偏差独立记录，不据此宣称主题目标全部通过。

本记录细化 ADR-0010 第 4 条，不改变既有三包、core 无 UI 依赖、宿主存储职责及完整界面／独立组件并行交付方向。首批只交付属性抽屉与表单预览；这不授权恢复工作台、表单设计器外壳或多框架接入。任意种子定制保留设计方向，未纳入首批实现。

具体公开配置名称、类型、继承与读取方式、浅深主题切换协议、弹层归属机制仍需后续规格提案审阅。本 ADR 只记录来源与兼容的行为决策，不把设计 JSON 或讨论中的接缝名称冻结成公开 API。
