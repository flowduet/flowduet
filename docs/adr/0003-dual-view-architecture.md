# ADR-0003：双视图架构 —— 递归组件 + Vue-Flow，一棵树两种投影

- 状态：Accepted
- 日期：2026-09-14

## 背景

钉钉式用户的心智模型是"在纵向列表里加节点、点开抽屉配置"；Vue-Flow 的强项（自由连线、缩放平移）对小白恰恰是负担。而 BPMN 视图需要自由画布。现有双模式方案几乎都是两套数据两层皮，互切靠有损转换。

**关键论点**：本项目的核心差异化是"两个视图共享同一棵模型树"，而不是"两个模式跑在同一个画布库上"。

## 决策

1. **钉钉式视图**：纵向递归组件 + 右侧抽屉属性面板（wflow 式交互），用最贴合该心智的载体；
2. **BPMN 视图**：Vue-Flow 自由画布 + 属性面板；
3. 两者**只是同一棵 moddle 模型树的两种投影**——互切 = 切换视图，不切换/转换模型；
4. **DI 布局是独立模块**（`DiLayout` 接缝）：
   - BPMN 视图导出：画布真实坐标直映射 `bpmndi:BPMNShape@bounds`；
   - 钉钉式视图导出：无画布坐标，由**自动布局器**生成 DI——否则导出的 XML 在其他工具里打开是空白。

## 被否决的备选

- **两模式都跑 Vue-Flow**：需要用图库模拟纵向列表交互（禁自由拖拽、隐藏连线），成本高、体验未必好；
- **v1 只做 BPMN 模式**：双模式是立项卖点，发布即违约。

## 后果

- 未来新增视图（如移动端预览）= 写一个新投影组件，内核零改动；
- 自动布局器是独立工作项：v0 用恒等映射（画布坐标），Step 3 起做层次/泳道布局（见 ROADMAP）；
- 属性面板需要按视图形态做两套交互皮肤，但读写同一套模型字段。
