# ADR-0005：引擎适配策略 —— 引擎无关内核 + 可插拔适配器，首发 Flowable

- 状态：Accepted
- 日期：2026-09-14

## 背景（2026-09 事实核查，详见 research/landscape）

- Flowable 开源版本线：6.8.x（JDK 8 / Boot 2，**国内存量主力**）→ 7.0.0（2023-12，强制 JDK 17 / Boot 3 / jakarta，删除表单引擎、内容引擎与 flowable-ui）→ 7.2.0（2025-08-21，7.x 末版）→ **8.0.0（2026-02-27，Spring 7 / Boot 4 / Jackson 3）**；
- 6→7 是断层升级，国内大量存量项目与脚手架（ruoyi-flowable 等）钉在 6.8；但 **flowable XML 方言（命名空间与扩展属性）跨 6/7/8 基本稳定**——变的都是引擎侧基线，设计器不可见；
- Camunda 7 CE 已 EOL（2025-10，最终版 7.24；EE 支持至 2030-04）；Camunda 8 = Zeebe 云原生重写，与 7 不兼容；国内开源审批盘子的默认引擎是 Flowable。

## 决策

1. 内核只面向标准 BPMN 2.0；引擎差异做成**可插拔适配器**，接口收敛为三个点：命名空间前缀、扩展属性 schema、任务类型映射；
2. **首发适配器按 flowable XML 方言实现（以 6.8 为基准）**；
3. CI 对 **6.8 / 7.2 / 8.0** 三版本做部署冒烟（编译产物真实部署验证）；
4. README 口径："**支持 Flowable 6.x–8.x**"。

## 被否决的备选

- **三引擎开箱通吃**（内置 activiti/flowable/camunda 三套支持，温良恭式）：维护 ×3，兼容包袱最重——适配器架构下这只是三个插件，不必捆在首发；
- **仅 Flowable 单引擎硬编码**：受众窄，且失去"引擎无关"的架构叙事；
- **首发对准 Camunda 8 / 国产引擎（Warm-Flow/FlowLong）**：竞争小但不在国内审批流主流盘子。

## 后果

- 适配器接口要小而稳，首发实现即接口的验收用例；
- Camunda 命名空间适配器留给 v1.x，社区需求驱动（本 ADR 不关闭此门）；
- 适配器无运行时引擎依赖（产物是 XML），"部署冒烟"是 CI 里的容器化 Flowable + REST 调用，不拖慢本地开发。
