# ADR-0009：流程设计文档与默认表单绑定

- 状态：Proposed（方向已确认，具体 XML 编码随迭代三书面规格审阅）。
- 日期：2026-09-24。
- 关联：[迭代三规格](../specs/iteration-3/README.md)、ADR-0002、ADR-0006。

## 背景

下一迭代需要把流程编辑与表单设计组成可保存、可恢复的闭环。仅导出 XML 无法携带表单定义，分别保存又要求每个宿主自行维护引用一致性。流程允许默认表单和节点覆盖，必须保留“继承”与“显式指定”的差别。

## 决策

1. 统一流程设计文档携带 BPMN XML 与文档内全部表单定义。流程结构及绑定以 XML 为事实源，外层 JSON 不另存一份可写绑定关系。
2. 表单定义属于独立表单领域；core 只负责引用协议，保持零 FormCreate 依赖。这细化了 ADR-0002 的事实源适用范围，遵循 ADR-0006 的分包原则。
3. 文档由宿主存储；FormCreate 集成包负责成套编解码与编辑装配。沿用 core、designer、form-create 三包，不新增工作台包，也不将可复用逻辑留在 Playground。
4. 节点显式 key 优先，否则继承流程默认；均未设置表示无表单。存在但无法解析的 key 明确报错，不回退，不静默清除。
5. 具体编码提案：`bpmn:Process` 上的 `flowduet:defaultFormKey`（`urn:flowduet:bpmn`）保存默认引用；节点沿用 `flowable:formKey` 保存显式覆盖。公共扩展由 core 统一注册；不将继承结果逐节点固化。
6. 保存草稿与部署导出是不同合同：前者允许业务配置未完成，后者要求流程配置与已声明的表单引用完整。恢复先校验并构建临时状态，成功后原子替换。
7. 本轮表单只在文档内复用；不引入跨流程共享库和表单版本管理。预览试填数据不属于设计文档。

## 考虑过的替代方案

- 分开交付 XML 和表单定义：宿主灵活，但每个接入方都要实现完整保存与一致性维护，不利于本轮集成闭环。
- 把完整表单 schema 嵌进 BPMN XML：单文件携带方便，但让 XML 承担大量提供者特有内容，扩展协议和编辑成本更高。
- 保存第二份节点到表单的 JSON 映射：读取方便，但会引入与 XML 冲突的双重事实源。
- 新增工作台包：职责更细，但当前只有一个表单提供者，增加的发布面与接口维护没有本轮需求支撑。

## 后果

单独导出的 BPMN XML 仍可交给引擎部署，但完整编辑恢复需要流程设计文档中的表单定义。默认继承由 FlowDuet 解析，不等于 Flowable 会自动加载或渲染表单。项目扩展的真实部署兼容性必须通过 Flowable 6.8 冒烟建立证据。

格式从首版带版本标识，未知版本明确拒绝。后续跨流程复用、多框架或运行时接入需另行设计，不把它们伪装成当前引用协议已经解决的问题。
