# ADR-0010：完整设计界面与独立组件并行交付

- 状态：Accepted（交付、宿主职责与分包方向）；具体接口待设计。
- 日期：2026-10-14。
- 讨论记录：[品牌与体验重设计讨论](../design/experience-redesign-discussion.md)。

## 背景

本轮希望统一双视图、属性面板和表单设计的完整体验，主要服务流程实施顾问，优先打磨从零配置流程与表单直至校验交付的路径。如果完整体验只存在于 Playground，npm 集成方仍需重复实现整体装配，难以直接复用重设计成果。

## 决策

1. npm 交付提供可直接嵌入的完整设计界面，同时保留可独立组合的组件。
2. 宿主负责存储与发布；完整设计界面通过后续明确的集成边界与宿主协作。
3. Playground 用于展示和验证完整集成体验，可复用的装配能力不应仅存在于 Playground。
4. 沿用现有三包：公共主题和流程组件由 `designer` 承担，完整流程与表单装配由 `form-create` 承担，`core` 保持无 UI 依赖，不新增工作台包。基础控件继续复用现有库，通过统一规范与适配形成 FlowDuet 风格。
5. 公开接口及实现细节需审阅书面提案后进一步细化；本决策不自动授权产品代码实施，也不自动增加 BPMN 编辑能力。

## 考虑过的替代方案

- 只提供独立组件，完整体验留在 Playground 供参考：接入自由度高，但每个集成方需要重复装配，难以直接获得本轮设计的完整体验。
- 优先交付独立应用：可集中打磨完整工具，但与本轮确认的组件嵌入目标不符。

## 后果

后续设计需同时检验整套界面嵌入与独立组件组合，避免默认整套界面成为唯一接入路径。存储、部署和业务后端不因提供完整界面而归入组件库职责。

本决策延续 ADR-0007 的 npm 组件交付方向和 ADR-0009 关于可复用逻辑不留在 Playground、沿用三包的原则。若真实组件验证表明需要改变分包，须另行提案。
