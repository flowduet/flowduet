# ADR-0004：仿钉钉模式的特性边界 —— 严格 BPMN 可表达子集

- 状态：Accepted
- 日期：2026-09-14

## 背景

XML 是唯一事实源（ADR-0002）⇒ 钉钉式视图画出的每个节点最终都必须落成合法 BPMN XML。
会签可映射多实例任务、条件分支可映射排他网关——这些没问题；但国内审批流的"中国特色"能力（**加签、减签、任意节点回退、空节点自动通过**等）在 BPMN 2.0 标准里没有表达，只能靠引擎扩展属性或运行时动态改流程定义实现。

## 决策

1. 钉钉式视图**严格限定为 BPMN 可表达子集的语法糖**：
   - 审批 → 用户任务；会签 → 多实例用户任务；条件分支 → 排他网关；并行 → 并行网关；抄送 → 脚本/邮件任务（或适配器扩展任务）；
2. 特色能力一律通过**引擎适配器的扩展属性**落地（如 `flowable:` 命名空间属性、任务/执行监听器），**不在模型层发明 BPMN 之外的私有节点类型**。

## 被否决的备选

- **允许私有特性 + 导出降级**：体验天花板更高，但 XML 事实源被悄悄破坏，两套行为长期分叉，"导出永远合法"的产品承诺无法兑现。

## 后果

- 任何钉钉式流程导出即为合法可执行 BPMN——写进 README 的硬承诺；
- 加签/回退的体验深度取决于适配器对引擎扩展属性的覆盖度，是 Flowable 首发适配器的核心工作项之一；
- 文档要向用户明示：钉钉式模式画不了 BPMN 表达不了的流程，这是特性（保真）而非缺陷。
