# ADR-0011：属性编辑容器与缓冲提交边界

- 状态：Accepted（用户已确认修订方案具备进入阶段零的条件；具体实现仍需探针验证）。
- 日期：2026-10-14。
- 补充：[ADR-0003](0003-dual-view-architecture.md) 第 1 条；不替代共享模型、投影和 DI 布局决策。

## 背景

ADR-0003 将钉钉式视图的属性配置限定为右侧抽屉。新工作台已选择固定面板，必须明确该变化适用于哪个入口，不能静默替换已发布独立组件的默认行为。

当前 `NodeDrawer` 以字段缓冲加“确定/取消”工作；`DingtalkDesigner.commitPendingChanges` 使用相同写模型路径。固定面板中的高频对象切换需要保留未完成输入，不能只复用抽屉的重新回填行为。

## 已确认决策

1. 新工作台使用固定属性面板，按对象维护输入缓冲，提供“应用/还原”。应用写入当前模型，不代表持久化保存；还原回到该对象当前模型值。
2. 切换对象或阶段不自动提交或丢弃输入。保存整份草稿时收集全部对象缓冲，无法合法收集时保留输入并明确反馈。
3. BPMN 视图维持只读且无对象选择，属性区展示流程级只读摘要；节点、分支问题定位回到钉钉式编辑视图，默认表单问题进入表单阶段。

## 兼容方案提案

独立 `DingtalkDesigner` 默认继续使用抽屉及现有显式提交合同；新工作台通过新增、显式启用的外置属性编辑接缝使用固定面板。字段编辑与校验逻辑复用，容器和缓冲生命周期分别适配，不能复制两套业务校验。

新接缝的准确 API、默认值与事件在前置探针之后形成合同。旧组件不因未传新配置就切换容器或提交语义；不得将新工作台的按对象缓冲语义悄悄施加给旧调用方。

## 后果

固定面板是新工作台的默认交互，抽屉是已有独立组件的兼容默认；两种呈现围绕同一模型合同，不形成第二份业务事实源。需要验证对象删除、文档替换、缓冲失效、保存收集和已有抽屉合同。

本 ADR 对 ADR-0003 第 1 条仅在新工作台的属性容器这一范围作补充；历史正文不改写。实施前仍需审阅探针计划和公开接口合同。

后续补充评审进一步指出对象生命期、表单缓冲和草稿级应用边界。其细化提案与验证用例见 [主提案 §3.1](../design/2026-10-14-design-system-workbench-proposal.md#31-跨阶段编辑连续性) 及阶段零计划，不以本 ADR 的 Accepted 状态代替运行验证。
