## 目标与边界

普通 npm 集成开发者在唯一完整体验宿主 Playground 完成设计表单→默认/覆盖绑定→保存草稿→重新打开→继续编辑与真实渲染试填；配置完整后能导出有效 BPMN XML。覆盖两表单、八类字段、默认值/必填/基础行列、四种审批形态、条件/并行/抄送回归、原子恢复、引用一致性及文件/存储/异步错误。

本轮使用 Codex 自带浏览器逐案执行，不以此前 Playwright 或单元测试结果冒充本轮通过。UI 普通路径与辅助故障/公开组件装配分开标记。任何工具无法执行或观察的路径记为阻塞，不按时间或代码推断自动通过；任何产品失败保留预期并记录最小复现。本轮仅设计及执行验收，产品缺陷另行记录。

显式范围边界：不执行真实发起/待办/审批操作，不做业务数据存储、节点字段权限、跨流程表单库、多框架、上传、远程数据、自定义脚本/联动、自定义组件、子表单/重复明细、复杂嵌套、可编辑 BPMN 画布或其他引擎扩展。导出 XML 只携带流程与绑定，不能替代带全部表单定义的设计文档。默认继承是宿主设计协议，不等于引擎自动渲染表单。

包 JS/TS/CSS、tarball 依赖、Flowable 部署、版本 PR/CHANGELOG/registry/tag 为独立交付门槛，已有记录见 `evidence/77-p2-fix-verification.md`；本轮产品浏览器计数不混入这些门槛，版本 PR/发布尚未执行。

## 数据、判定与执行规则

- S1：完整两表单“申请与复核”，八字段 + 顶层两列栅格及列内字段；经理继承申请单，合同/财务覆盖复核单。保留条件、并行、抄送。
- 字段默认：中文、多行换行、数字0、单选/下拉字符串0、多选未设置/[]/[1]、日期2026-10-12、开关false。必填按类型语义判定，不把0/false误判为空。S2：含第三张未绑定表单；S3：审批人和条件未完成的业务草稿；B：不同名称/目录的另一个合法文档。
- 目录、字段ID及规则/options比较实际下载或本地落盘的完整定义；XML按元素ID、连线、绑定及审批语义核对，不把所有字符串字节差异都当业务差异。
- 每次拒绝前制造未保存修改；观察模型、目录、当前输入、dirty、定位及后续可用性，不能只看一条报错文案。
- 原有本地草稿先备份；仅测试自己的数据。每个注入恢复原方法，全部结束恢复原草稿。下载/实际文件选择与工具读取反馈分别记录。
- 状态：待执行 / 执行中 / 通过 / 失败 / 工具阻塞 / 不适用。每项保存步骤、实际结果、操作方式、证据路径。计数逐项汇总，参数分支不能默认为全部通过。
