# #75 设计文档兼容与原子打开产品功能验收用例

依据：#75、PR #87、迭代三 A11–A13/A20。用例先定义预期，实际结果另记 `evidence/75-codex-browser-acceptance.md`。

本轮在 Playground 生产预览与 Codex 自带浏览器执行，版本固定 `acc4d4e`。范围包括恢复兼容、业务草稿与结构拒绝、原子保留、URI 使用与作用域、三项复审修复、实际保存下载重开及继续编辑。八字段只验已开放内容可恢复，不重复 #74 完整字段设计矩阵；不包含引擎部署、运行时审批、跨流程库、npm 发布。

## 执行约定

- 输入文件由 `evidence/75-browser-fixtures/manifest.json` 索引，单因素变体；表单布局正例复用有来源的 #74 八字段夹具。
- 每个正例：打开对应文件，确认状态、流程可见及目录；完整配置导出 XML，草稿须明确阻断；指定的附加步骤逐项执行。
- 每个拒绝用例：先持有 baseline 的合法流程和两张表单，在界面改出未保存标记；从文件打开变体，确认可定位错误；再导出当前 XML 并检查流程、绑定和审批人未变，表单目录与编辑标记仍在。
- 不以页面“已保存”提示替代下载文件内容检查；若原生选择器/下载有限制，记录辅助方法或证据缺口。
- 浏览器不能验 core 未开启严格选项的直接调用合同，此项使用本轮 PR 源码测试/CI 作为旁证，不能标作浏览器通过。
