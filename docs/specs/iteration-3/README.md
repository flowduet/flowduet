## 目标与成功标准

让普通 npm 集成开发者在 Playground 中完成：设计表单 → 绑定流程 → 保存草稿 → 重新打开 → 继续编辑与试填；配置完整后，流程 XML 继续通过 Flowable 6.8 部署冒烟。

目前没有明确的真实业务接入项目。本轮证明公开包能够支撑这条设计闭环，不将演示验收等同于真实业务适用性验证。

Playground 是唯一长期维护的演示与体验验收宿主。仓库外临时工程只用于安装包检查，不新增第二套演示应用。该检查复用贡献指南已有的 tarball 消费流程，扩展至新增表单包。

## 已确认范围

1. 流程可指定默认表单；单签及三种多人审批节点可指定另一张表单覆盖默认选择。
2. 多个节点可引用文档内同一张表单；跨文档没有共享引用或自动更新关系。
3. 统一流程设计文档携带 BPMN XML 和全部文档内表单定义，宿主负责存储。
4. 未完成业务配置的设计草稿可以保存和恢复；部署导出执行完整校验。
5. 仅接入 Element Plus，使用 FormCreate 开源设计器与渲染能力；其他 UI 框架仍属后续 v1 工作。
6. 表单支持文本、多行文本、数字、单选、多选、下拉单选、日期单值、开关，以及默认值、必填校验与基础行列布局。
7. 表单管理支持新建、改名、编辑、删除和选择绑定。表单 ID 稳定，名称修改不影响引用。
8. 预览允许试填、执行必填校验并查看当前值；试填值不写回表单定义、不随设计文档保存。
9. 交付 core、designer 的相应新版本及 form-create 首个公开 alpha 版本；版本由 Changesets 按实际变更决定。

## 显式边界

- 本轮不做真实发起流程、待办、审批操作、业务数据存储或运行时表单加载。
- 不做节点级字段权限或节点级必填配置；必填属于表单自身定义。
- 不做跨流程表单库、表单发布版本或跨文档复制入口。复制整个设计文档后，两份内容独立。
- 不做子表单、重复明细、上传、远程数据源、自定义脚本、表达式联动或自定义组件接入。
- 不做 BPMN 可编辑画布、新流程元素或多引擎版本扩展；保持既有五类节点与只读投影。
- 首版恢复承诺面向本格式及当前可编辑的流程子集，不新增任意第三方 BPMN 编辑或自动迁移能力。
- 导出 BPMN XML 仍只携带流程与绑定引用。它不包含完整表单定义，不能替代流程设计文档备份。

## 模块职责与兼容性

| 模块                    | 本轮职责                                                       | 对外边界                                                                      |
| ----------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `@flowduet/core`        | 默认表单及节点覆盖的模型读写、有效引用解析、XML 往返           | 不依赖 FormCreate，不读取表单 schema，不实现存储                              |
| `@flowduet/designer`    | 流程默认选择入口、节点覆盖入口、草稿配置与部署导出区分         | 接收中立的表单选项，不依赖 FormCreate；保留原有独立使用方式                   |
| `@flowduet/form-create` | 常用字段设计与预览、表单管理、流程设计文档编解码及完整编辑装配 | 依赖 core/designer 的公开入口，封装 FormCreate 特有行为；由宿主保存返回的文档 |
| `apps/playground`       | 装配完整体验，执行保存、打开、文件下载及导入                   | 使用公开包接口，不访问包内部文件，不重复实现文档或绑定算法                    |

不增加第四个公开包。表单包应提供可直接使用的组合编辑入口，同时公开保存、恢复、有效表单查询和预览所需的最小接口；具体符号及 Vue 接口在实施计划中列明。

原 `DingtalkDesigner`、`BpmnCanvas` 和 `exportXml(model)` 的接入方式继续有效。未装表单包的宿主保留手写 `formKey` 的能力；启用文档内表单集成后，节点使用选项选择与继承提示。已有手写但在文档中不存在的 key 显示为失效引用，保留原值供修复，不静默清除或改为默认值。

## 绑定协议

### 选择语义

1. 节点指定覆盖 key 时，以该 key 查找表单；查找失败报引用失效。
2. 节点没有覆盖 key 时，使用流程默认 key；查找失败同样报引用失效。
3. 两者均未指定时，有效表单为空，是合法的纯流程场景。
4. 清除节点覆盖表示恢复继承。本轮不增加“忽略默认并强制无表单”第三种节点状态。
5. 修改默认表单只影响继承节点；覆盖节点保持原选择。单签与多人形态互换保留覆盖 key。
6. 默认继承是 FlowDuet 的设计协议，宿主可使用公开解析能力；不宣称 Flowable 引擎会自动继承或渲染表单。

### XML 落点提案

以下是对已确认语义的具体编码方案，随本书面规格一起审阅：

- 在 `bpmn:Process` 上使用项目扩展属性 `flowduet:defaultFormKey`，命名空间 URI 为 `urn:flowduet:bpmn`。
- 节点覆盖继续使用现有 Flowable 适配器中的 `flowable:formKey`，不复制为第二份覆盖字段。
- 项目默认绑定描述符由 core 的创建和解析路径统一注册，与引擎适配器扩展包合并；保留既有适配器合同。扩展包前缀冲突应明确拒绝。
- 注册描述符不等于给所有 XML 强加默认表单属性；未使用此功能的既有基准 XML 必须保持原合同。
- XML 保存覆盖意图，不将继承结果逐节点写成显式覆盖；否则以后修改默认表单将失去继承语义。
- 表单引用是经过 trim 的非空字面 key，不计算表达式。不改写旧入口对既有节点 `formKey` 的合同；集成模式通过目录引用检查限制其有效范围。

该扩展的往返与 Flowable 6.8 部署验证是实现早期门槛。若所选编码不可被引擎接受，应修订本方案并复审，不能悄悄把绑定移到文档 JSON 中形成第二事实源。

## 流程设计文档

### 首版结构提案

外层使用 JSON，可序列化为文件或交给宿主存储。协议字段如下：

| 字段      | 约定                                                           |
| --------- | -------------------------------------------------------------- |
| `format`  | 固定标识 `flowduet.design`                                     |
| `version` | 整数 `1`，表示文档协议版本，不是流程或表单发布版本             |
| `engine`  | 本轮为 `flowable`；不从未知值猜测适配器                        |
| `xml`     | 单流程 BPMN XML，包含流程结构与表单绑定                        |
| `forms`   | 表单定义数组，包含文档内全部表单，包括尚未绑定但仍在设计的表单 |

每个表单定义包含稳定、文档内唯一的 `id`、非空 `name`、固定提供者标识 `form-create/element-plus`，以及 `rules`、`options` 两段序列化字符串。二者使用匹配版本的 FormCreate 序列化接口成对保存、恢复；不能只保存字段规则而丢失布局及表单配置。

外层格式只封装内容，不重复存储默认 key、节点到表单的映射或另一份流程 JSON。内存中的绑定摘要可从 XML 模型派生，不能成为独立可写状态。

表单 ID 由新建动作生成，用户不能通过改名改变 ID。字段标识在单张表单内唯一，表单改名或重新打开不会重新生成字段标识。组件支持范围以本规格为准，导入超出范围的表单规则时明确拒绝，不能静默删去后再保存。

### 保存与部署导出

**保存设计文档**检查内容可序列化、流程结构能被本轮编辑器恢复、文档标识和表单定义结构有效。审批人、条件或表单引用未配齐属于业务草稿，不阻止保存；保存结果同时报告待修复项。

**部署导出**在组合入口执行现有流程导出校验和表单引用完整性校验，全部通过才产出部署 XML。配置了默认或节点 key 时，它必须在文档内存在；没有配置任何表单仍可导出。即使默认表单当前没有被继承，也应修复它的失效引用再导出。

底层 `exportXml(model)` 继续只负责它已掌握的流程校验，不假装能验证未传入的表单目录。表单包的组合导出入口负责补齐引用检查，Playground 使用组合入口。

抽屉与表单编辑器中的当前设计变更必须在保存快照前收集。草稿允许缺失业务配置，但不允许半写结构、无法序列化的规则或丢失编辑内容。已有字段格式与模型结构守卫继续生效。

保存文档会生成可恢复的 DI；不得把试填值混进字段默认值。部署导出失败时清除或明确标记旧导出结果，避免将上一次有效 XML 当作当前设计。

### 原子恢复与错误处理

先在临时状态中完成外层格式校验、表单规则恢复、XML 解析、流程可编辑结构检查及引用诊断，成功后一次替换当前模型和表单目录。

- 无效 JSON、错误格式标识、不支持的版本/引擎/提供者、重复表单 ID、无法恢复的规则或 XML：拒绝打开，保留当前设计及未保存状态。
- 解析器报告不能无损识别的语义、多个流程或超出本轮编辑子集的结构：组合打开入口拒绝，不能只选第一个流程或静默丢弃内容。无需改写旧 `parse` 入口的通用能力。
- 业务字段缺失、表单引用失效：可打开为草稿，明确展示定位信息，供用户补齐。
- 预览目标引用失效：该目标预览显示错误；其他有效表单仍可独立预览。
- 删除被流程默认绑定或任何节点引用的表单：拒绝并列出引用位置；先调整绑定再删除。
- 同时发生两次打开或异步序列化时，旧请求不得覆盖新状态。文件读取和浏览器存储失败必须反馈，不能显示保存成功。
- 文档版本首版只接受 `1`，未知版本不自动迁移或降级。

## Playground 用户流程

同一应用提供流程编辑、表单管理和试填预览入口；BPMN 视图继续只读并共享当前模型。

1. 打开示例或新建设计；新建设计含可编辑的最小流程，表单目录可以为空。
2. 新建“申请单”，添加常用字段，设置默认值及必填；将其设为流程默认表单。
3. 新建“复核单”，让一个审批节点覆盖默认选择，其余节点显示继承来源。
4. 预览指定节点的有效表单，试填并触发校验；切换预览目标时重置临时试填状态。
5. 点击“保存草稿”，由 Playground 写入浏览器本地存储；提示保存结果及尚未完成的配置。另提供设计文档下载和文件打开，以验证可携带性。
6. 刷新后读取已保存草稿，再打开时恢复流程、表单、绑定及配置；有未保存修改时，打开文件或新建设计需提示替换影响。
7. 配齐流程和引用后点击“导出 BPMN XML”；将当前有效导出物用于 Flowable 6.8 冒烟。

表单 UI 使用开源设计器现有能力，限制本轮支持的组件与配置入口。基础布局为行列及字段顺序，不引入复杂栅格嵌套、重复数据容器或独立页面布局系统。

| 阶段       | 交付内容                                | 完成条件                                              |

## 验证与发布

- 沿用编译合同、往返保真与适配器合同，新增默认绑定/覆盖以及完整文档的往返断言。
- 覆盖不同表单 ID 同名、修改默认、清除覆盖、单签/多人切换、删除引用中的表单及失效 key；验证试填不会改写设计定义。
- 验证打开失败无部分覆盖，缺少业务配置可恢复为草稿；不使用仅模拟导出成功的测试代替真实组件链路。
- 执行项目既有 lint、test、build 和 CI 门槛；文档-only 的规划阶段不宣称已执行这些产品验收。
- 扩展现有 tarball 外部消费检查至三包，覆盖 JS 入口、TS 类型、CSS、依赖解析及一次设计文档保存/恢复；浏览器确认表单组件实际渲染。
- 保留现有 Flowable 6.8 冒烟；新增含默认引用和显式覆盖的有效流程基准，并部署 Playground 实际导出物。
- 发布继续遵循贡献指南的版本 PR、Changesets 人工发布与官方 registry 读回；不在本轮切换到 CI 自动发包。
- 新表单包从 private 占位转为公开 alpha；同时补齐 README、样式/类型入口、LICENSE 及三包发布说明。具体版本号在版本 PR 核定，不提前占用版本。

## 依赖与事实依据

计划新增的外部依赖为 FormCreate 开源设计器及兼容的 Element Plus 渲染器；Vue、Element Plus 沿用现有技术栈。具体包版本和 peer 依赖应在实施第一步通过 npm 镜像元数据与对应上游源码核定并锁定，避免混用文档中的 `next`、旧包名与不同版本渲染器。计划不含 Pro、AI 助理或商业组件。

- [FormCreate 开源设计器仓库](https://github.com/xaboy/form-create-designer)：公开设计器与 Element Plus 接入入口；需要按选定版本核对组件和包依赖。
- [FormCreate 序列化接口](https://www.form-create.com/v3/guide/global-api)：规则及对象的序列化与恢复能力，是表单包封装的基础。
- 当前项目 `core` 已有 `parse`/`compile`，节点 `formKey` 已有往返测试；`designer/export.ts` 集中执行草稿字段扫描；`form-create` 仍为占位包。
