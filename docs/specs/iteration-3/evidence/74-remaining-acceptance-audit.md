# #74 剩余用例核查（2026-09-30）

接续 [Chrome 文件补验](./74-chrome-browser-acceptance.md)，使用系统 Chrome 154 和本地 Playground 生产构建，核查首次报告仍标为部分完成的 F01、F04、F13。本轮没有修改产品代码。

## F01：静态选项范围泄漏，失败

组件菜单只有八类字段和栅格；八类字段的实际配置面板均显示默认值入口。普通输入框没有切换到其他原生输入类型的入口，组件联动、编辑数据、远程数据源和脚本入口也未出现。

但“选择器”配置面板仍可打开“是否可搜索”和“是否允许用户创建新条目”。在 UI 中开启两项并保存后，下载规则包含 `props: { allowCreate: true, filterable: true }`；经理审批的真实预览允许输入并选中不在静态选项表中的“临时新选项”，“当前试填值”也记录该字符串。复现输出留存为 [`select-allow-create-ui.flowduet.json`](./74-browser-fixtures/select-allow-create-ui.flowduet.json)。保存、打开守卫目前不拒绝 `allowCreate`。

**判定：F01 失败。** 下拉单选的静态选项范围存在可用的越界入口。建议隐藏创建新条目配置，并在保存/打开共用守卫拒绝启用的 `allowCreate`；单纯的本地静态选项搜索可保留。

## F04：显式空多选默认值在设计器保存后丢失，失败

逐项通过真实面板操作默认值：文本与多行文本改为中文新值，数字先改 `7` 再改 `0`，单选和下拉改为字符串 `"2"`，日期改为 `2026-10-01`，开关先改开启再改关闭。保存并下载后，这些值的类型与内容均符合预期。

多选字段从默认 `["1"]` 清除最后一个标签后，下载规则不再有 `value` 键；通过键盘再次选中、取消选中，结果相同。另以明确含 `value: []` 的[输入文档](./74-browser-fixtures/checkbox-empty-input.flowduet.json)验证边界：直接打开并下载仍保留空数组；进入真实设计器、不改该字段而直接保存后，[输出文档](./74-browser-fixtures/checkbox-empty-after-editor.flowduet.json)删除了 `value` 键。两侧 JSON 的多选规则检查结果分别为 `hasValue: true, value: []` 和 `hasValue: false`。

当前依赖 `@form-create/designer` 3.5.0 的 `FcDesigner.vue` 中，`getJson()` 经 `parseRule()` 输出；后者会移除所有空数组规则属性。项目封装继续使用提供者的 `getJson()/getOptionsJson()` 成对出口，所以问题发生在真实设计器保存环节，流程文档直接打开/保存并不丢失该值。

**判定：F04 按当前用例中“未设置与显式空数组可区分”的要求失败。** 原始 #74 和 A10 要求默认值往返语义等价，但没有单独规定空多选与未设置是否必须区分。修复前需确认这两个状态的产品语义：严格保留显式 `[]`，或明确将二者归一为同一种空选择。

## F13：保存与打开边界已有证据，通过

首次内置浏览器报告已记录：顶层重复字段 ID、栅格列内与顶层重复 ID 的文档均被明确拒绝并点名重复值。真实设计器的字段 ID 输入框为只读，普通 UI 无法手工造出重复 ID；保存侧改由真实 `FormManager` 组件测试验证“重复字段标识不能关闭编辑器或上报保存”，本轮定向复跑 1 项通过。规则树测试“栅格列内字段的标识参与全树唯一性与非空校验”定向复跑 1 项通过。

**判定：F13 通过。** 打开侧有浏览器反馈，保存侧有组件边界与全树守卫测试；UI 手工构造重复 ID 不适用。

## 当前出口

F01 与 F04 是已复现的产品范围/默认值语义问题，PR #84 目前不满足 #74 全部验收条件。此前 F09/F10 的 Chrome 补验使用非空多选默认值，不能覆盖本轮发现的显式空数组路径；该补验对其记录的输入场景仍成立。Node 22/24 CI 通过仅说明现有自动化未覆盖这些路径，不能代替本轮失败用例。
