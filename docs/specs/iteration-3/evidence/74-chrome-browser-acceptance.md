# #74 Chrome 下载与试填补验（2026-09-29）

接续 [内置浏览器补验](./74-browser-followup-acceptance.md)。本轮使用系统 Google Chrome 154（CDP 端口 9222）访问本地 Playground 生产构建 `http://127.0.0.1:5199/`，只补 F09、F10 的实际下载文件证据。输入为仓库留存的 [`valid-full-fields.flowduet.json`](./74-browser-fixtures/valid-full-fields.flowduet.json)；Chrome 首次下载的产物经 Prettier 排版后留存为 [`roundtrip-chrome-downloaded.flowduet.json`](./74-browser-fixtures/roundtrip-chrome-downloaded.flowduet.json)。下述字节数、SHA-256 和 `cmp` 结果均来自排版前的四份实际下载文件。

## F09：两轮下载与打开

1. 在页面打开合法全字段文档，页面显示“已打开设计文档”；流程默认表单为“全字段验收单”，经理审批等节点显示继承默认。
2. 点击“下载设计文档”，取得 `round0.flowduet.json`。点击“新建设计”，确认当前设计已替换，再从该文件打开并下载 `round1.flowduet.json`。
3. 再次新建设计，从 `round1` 打开并下载 `round2.flowduet.json`。两次打开均显示成功。
4. 三份下载文件均为 **13,749 字节**、SHA-256 均为 `761e0b5ba883932ee03740d195081f861d4431b5b13c6f5319ff5e04e4e12400`；`cmp` 比对 `round0=round1`、`round1=round2` 均退出 0。JSON 含一张表单、九项顶层规则（八类字段与一组栅格）、对象型 `options`，XML 保留 `flowduet:defaultFormKey="form_1"`。

**判定：F09 通过。** 两轮真实下载、重新打开后的文件逐字节相同，覆盖规则、选项、默认值、顺序、布局和绑定的语义等价要求。

## F10：试填前后设计文件隔离

在第二轮恢复的经理审批预览中，分别将文本改为“试填事由”、多行文本改为“试填说明”、数字改为 `9`、单选改为字符串 `"2"`、多选增加 `"2"`、下拉改为字符串 `"2"`、日期改为 `2026-10-01`、开关改为 `true`，并填写列甲“试填列甲”、列乙 `2026-10-02`。预览的“当前试填值”逐项显示上述值。

关闭预览后下载 `after-trial.flowduet.json`：文件仍为 **13,749 字节**，SHA-256 与 `round2` 相同，`cmp` 退出 0。再新建设计并从 `after-trial` 打开，经理审批预览恢复文本“默认事由”、多行文本“默认说明”、数字 `0`、单选/下拉 `"1"`、多选 `["1"]`、日期 `2026-09-29`、开关 `false`；列甲、列乙没有试填值。

**判定：F10 通过。** 十个可试填字段的当前值在界面变化，但下载的设计文档与试填前逐字节相同；从该文件重开后只显示设计默认值。

## F12：单文本最小链路补验

另从新建设计开始，在表单管理中新建“文本最小链路”，通过设计器添加唯一输入框，保存内容并设为流程默认表单。Chrome 下载得到 2,891 字节的设计文档：一张表单、一条 `input` 规则，XML 默认引用为 `form_1`。再次新建设计后从该文件打开，审批节点显示继承默认；预览输入“文本回归通过”，“当前试填值”显示该值。**判定：F12 的最小设计、绑定、下载、打开、试填链路通过。** 必填校验已在 F05 独立验证，本轮未给该最小字段额外配置必填。
