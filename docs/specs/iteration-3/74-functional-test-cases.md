# #74 常用字段与基础布局功能测试用例

依据：[实施 Issue #74](https://github.com/flowduet/flowduet/issues/74)、[父规格 #70](https://github.com/flowduet/flowduet/issues/70)、[迭代三验收清单](./ACCEPTANCE.md)的 A09、A10、A13。本文件定义可重复执行的产品用例；实际运行结果另记在 `evidence/`，不把预期写成已通过。

## 测试数据与判定方式

- 在 Playground 新建一张“全字段申请单”，先沿用单张流程默认表单链路。八类字段分别使用稳定的字段标识；栅格列内另放两个字段，用于检查整棵规则树的唯一性。
- 静态选项分别设为 `是=1`、`否=0`。文本、多行文本默认值为中文字符串；数字用 `0`；单选和下拉用字符串 `"0"`；多选用 `[]` 和 `["1"]`；日期用单值 `2026-09-29`；开关用布尔 `false`。
- 每个用例同时核对界面反馈与可观察的文档/预览结果。下载文件不可取得时，仅判定已在页面观察到的部分；不把页面提示“保存成功”等同于下载产物保真。
- “明确拒绝”指错误在界面可见、指出问题类型，当前流程、表单及未保存编辑内容保持原样。对导入边界使用基于合法设计文档制作的单项变体，每次只改变一个条件。

| 编号 | 操作                                                                 | 预期结果                                                                       | 来源                    |

| F14  | 导入字段标识缺失/空白、规则不是 JSON、`options` 不是 JSON 对象的文档 | 明确拒绝并说明结构问题；当前设计与未保存内容保留                               | #74 序列化错误、A12/A13 |
| F15  | 分别导入 `upload`、子表单/重复明细等范围外组件                       | 明确拒绝并指出类型；不会只保留认识的字段                                       | #74 范围、A13           |
| F16  | 分别导入普通输入框的非文本形态、下拉多选/远程搜索、日期多值/范围形态 | 明确拒绝对应形态；合法文本、下拉单选、日期单值仍可打开编辑                     | #74 形态边界、A13       |
