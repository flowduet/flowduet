## 手验流程

在 playground 以 UI 操作建立五类节点全谱流程（导出物：`acceptance-handover-flow.xml`，与编译产物逐字一致由组件联动保证）：

- 开始 / 结束事件；
- 审批（经理审批，`${manager}`）；
- 多实例：合同会签（会签，集合变量 `approvers`，formKey 占位）、财务复核（会签）、法务复核（依次，集合变量 `chain`）；
- 条件分支（`${amount > 1000}` + 默认分支）；
- 并行分支（财务复核 ∥ 法务复核）；
- 抄送（ccTo + 占位 delegate）。

## 抄送宿主合同边界（实测确认）

- 部署合法：含占位 delegate 引用的流程**部署与启动均不要求 bean 在场**；
- 执行合同：执行到达抄送节点时需宿主绑定名为 `flowduetCcTask` 的 delegate——缺失时引擎报 `Unknown property used in expression: ${flowduetCcTask}`（本次实测复现），事务回滚至会签完成态；
- 语义核对：抄送不在启动即执行路径时（本次 amount=500 走默认支路场景，或抄送仅作旁路知会），实例正常推进——「部署合法、执行归宿主」的 R3 口径与实测一致。

## 附：发现与处置记录

- 首次手验曾因误插抄送节点于启动路径（start 即执行 → 必然触达合同边界）而启动失败，经 UI 删除该节点后全链通过——属操作失误，非产品缺陷；同步确认演示 demo 主链含抄送节点时启动不报错（抄送在两个用户任务之后）。
