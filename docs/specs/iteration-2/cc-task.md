# Spec：抄送节点（服务任务 + 适配器扩展属性）

- 状态：**骨架**——拆票前成稿
- 所属包：`packages/core`（模型 / 适配器）
- 域术语：见 CONTEXT.md「抄送」

## 目标

模型层新增抄送节点，方言落为 `bpmn:ServiceTask` + 适配器扩展属性（收件人列表）；使适配器合同「扩展属性注入点」获得首个真实消费者。

## 已定决策

- 模型层是「抄送」语义节点，**不在模型层发明 BPMN 之外私有节点类型**（ADR-0004）；
- 方言形态 = `bpmn:ServiceTask` + 适配器扩展属性承载收件人；知会行为（站内通知等）由宿主提供的 delegate 实现，内核与适配器不管运行时行为；
- 被否决的 Mail 任务形态（`flowable:type="mail"`）：绕开扩展属性注入机制，且把站内知会心智绑死在邮件语义上。

## 待细化（成稿时逐项钉死）

1. 扩展属性 schema：收件人属性的命名空间、属性名、多值表达形态（表达式列表）——作为适配器「扩展属性 schema」要点的首个实例，合同测试随之扩展；
2. ServiceTask 无实现类的执行语义核查：冒烟验证部署合法性；spec 需写明宿主 delegate 合同（`delegateExpression` 约定或扩展属性驱动的实现约定）；
3. 模型 API：`addCcTask(spec)` 或 `addTask("cc", spec)`（经任务类型映射的引擎中立路径）；
4. 往返保真：扩展属性在 `parse → compile` 的保留；
5. 基准文件：含抄送节点的最小流程一份。

## 验收要点

- 适配器合同：扩展属性注入点有真实消费者的合同测试；
- 编译合同 / 往返保真 / Flowable 6.8 部署冒烟通过。
