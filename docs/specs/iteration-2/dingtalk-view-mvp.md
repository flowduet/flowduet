# Spec：钉钉式视图 MVP（递归组件 + 抽屉 + playground 宿主）

- 状态：**骨架**——拆票前成稿
- 所属包：`packages/designer`（视图）、`apps/playground`（验收宿主）
- 上游依据：ADR-0003（双视图架构）、ADR-0004（钉钉式边界）

## 目标

钉钉式视图五类节点可编辑：纵向列表加节点、抽屉里配置，一切编辑操作直接落在 `BpmnModel` 模型树上（投影，无中间数据形态）；playground 最小页面作为验收宿主。

## 已定决策

- 节点边界五类：审批、条件分支、会签、抄送、并行分支；
- 技术栈：Vue 3 + Element Plus（与 ADR-0006 form-create EP 基座同构）；
- 抽屉字段面：最小集（节点名、审批人、完成方式三档、条件表达式、默认分支、抄送收件人）+ formKey 占位字段；监听器 / 扩展属性面板 / 表单绑定协议不在本 spec；
- 交互参照 wflow 式心智：列表加节点、抽屉配置；条件分支与并行分支是「块容器」节点，内部递归嵌套子节点。

## 待细化（成稿时逐项钉死）

1. **几何来源（本迭代最隐蔽的交叉点）**：内核 `NodeSpec.shape` 目前必填，而钉钉式编辑天然无画布坐标——需要「竖排坐标推导」为无坐标节点生成几何（恒等布局的朴素自动布局雏形），否则只读投影与 XML 导出无 DI 可写；推导放内核、视图层还是独立布局模块，成稿时定；
2. 状态管理：模型树绑定方式——直接读写 `BpmnModel` + 响应式包装层，还是引入轻量 store；变更通知与视图刷新的边界；
3. 组件树：五类节点的递归渲染结构、块容器的折叠交互、加节点按钮的插入位置语义（当前节点后 / 分支内末尾）；
4. 抽屉交互流：字段读写直接落模型树；三档完成方式的切换联动（多实例属性）；
5. playground 页面结构：钉钉式编辑区 | BPMN 只读区 | XML 导出预览三区布局与联动。

## 验收要点

- playground 内以五类节点搭建最小审批流 → 导出 XML → Flowable 6.8 真实部署成功；
- 抽屉每次读写均直接反映在模型树上（与只读投影共享同一实例，零转换）；
- designer 以 `@flowduet/designer` 公开发布并被 playground 消费。
