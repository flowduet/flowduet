# Spec：并行网关 + 排他网关默认流转

- 状态：**成稿**（2026-09-20；grilling R2 + prototype 良构检查结论折入，拆票依据）
- 原型依据：分支 `prototype/iter2-vertical-layout-mi`（deriveBlockTree 良构检查已验证）
- 域术语：CONTEXT.md「并行分支」「条件分支」

## Problem Statement

审批流配置者需要「多条支路同时推进、全部完成后汇合」的并行分支，以及条件分支里「其余情况走这条」的默认支路。当前内核只有排他网关且无默认流转——并行结构建不出，条件全部不命中时流程会卡死在网关上（运行时无路可走）。

## Solution

内核新增并行网关建模与排他网关默认流转：默认流转以**分支侧标记**表达（调用方心智对齐钉钉式抽屉「本分支设为默认」），内核内部落 BPMN 网关 `default` 属性并守卫合法性。

## User Stories

1. 作为审批流配置者，我想添加并行分支，这样多部门同时审批互不等待。
2. 作为审批流配置者，我想并行支路全部完成后流程才继续，这样汇合语义符合直觉。
3. 作为审批流配置者，我想给条件分支设默认支路，这样不满足任何条件时流程仍有路可走。
4. 作为审批流配置者，我想默认支路在抽屉里是个开关，这样不必理解网关属性就能配置。
5. 作为宿主开发者，我想在一处声明默认分支（建分支时标记），这样不必先建分支再回填网关引用。
6. 作为宿主开发者，我想非法组合被立即拒绝，这样错误不潜伏到部署或运行时。
7. 作为 Flowable 运维，我想含并行与默认流转的 XML 部署一次通过。
8. 作为 BPMN 老手，我想导出的 `default` 属性与标准形态一致，这样其他工具打开不报错。
9. 作为内核嵌入开发者，我想并行结构不完整时（如分支不收敛）得到明确报错，这样不会导出语义破碎的流程。

## Implementation Decisions

- **建模 API**：`addParallelGateway(spec)` 与既有 `addExclusiveGateway` 对称；`SequenceFlowSpec` 新增默认标记（`default: true`），内核写源网关的 `default` 属性——BPMN 语义归网关、调用面归分支（grilling R2 决策）。
- **三重守卫（建模即抛错）**：
  1. 默认标记与 `condition` 同传；
  2. 默认出线的源不是排他网关；
  3. 同一网关的默认标记多于一条。
- **并行良构不在建模时强校验**（增删中间态会误伤合法编辑），收敛到编译/布局时的**块树良构检查**：分支不收敛（直撞结束事件）、交错收敛 → 显式抛错（原型 `deriveBlockTree` 已实现并验证，宁可拒绝不出重叠几何/破碎语义）。
- 默认流转的 DI 与普通连线一致处理，无特殊几何。

## Testing Decisions

- **编译合同**：两份新基准——并行分裂-汇合最小流程、带默认分支的排他网关流程（均含 bpmndi），逐字一致。
- **往返保真**：`default` 属性与并行结构 `parse → compile` 语义等价；默认分支往返后不产生条件表达式。
- **守卫行为**：三重守卫的抛错断言（外部行为：错误信息可读、指明违规元素）。
- **良构行为**：分支不收敛、交错收敛两类反例图的抛错断言（原型已有用例可搬）。
- **冒烟**：两份基准 6.8 部署注册。
- 先例：`minimal-flow` 基准链、原型 `vertical-layout.play.test.ts` 的良构反例。

## Out of Scope

包容网关、事件网关、活动级默认流转（BPMN 允许 Activity 出线设 default，MVP 限排他网关）、并行块的 UI 折叠交互细节（视图 spec 管）。
