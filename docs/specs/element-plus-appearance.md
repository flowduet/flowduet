## 问题陈述

FlowDuet 的品牌设计基线已经批准，但真实组件尚未消费统一的视觉规则。集成开发者目前会遇到属性抽屉与表单预览配色、尺寸和提示样式不一致的问题，也没有经过验证的实例外观配置，可以在融入宿主与使用 FlowDuet 品牌预设之间选择。

独立 HTML 样稿与源码映射不能证明真实 Element Plus／FormCreate 字段、弹层、焦点和输入保留正确。直接让所有旧调用切换到新外观，又会把升级风险转嫁给现有集成方。因此，本批交付必须具备明确的启用方式、局部覆盖范围、旧路径兼容与公开包消费证据。

## 解决方案

首批交付 Element Plus 路线的两处真实能力：通过 `DingtalkDesigner` 使用的节点属性抽屉，以及 `FormPreview` 的当前八类字段与真实可达弹层。两处都通过验收才算本批完成。

宿主显式启用新适配后，默认配色跟随宿主，可显式选择 FlowDuet 品牌预设；支持浅深主题（跟随宿主时与宿主当前主题一致，品牌预设时可按实例选择）、舒适 32px／紧凑 24px 两档密度，舒适默认。运行中切换外观保留属性输入与试填值，同页实例及其弹层互不串扰，无关宿主控件不受影响。未启用时保持旧调用的外观和行为。已有表单显式配置优先，新适配只补默认值。

长期以同一套视觉语义分别适配各 UI 库的主题机制。首批仅落地 Element Plus，不以本次交付承诺 Ant Design Vue 等其他框架已兼容，也不恢复完整工作台或历史供应商实验。

## 实现决策

### 1. 模块与交付边界

沿用现有三包。公共外观能力与流程组件由 designer 承担，FormCreate 预览侧消费同一合同；core 保持无 UI 依赖。两处入口可独立消费，不新增主题包、工作台包、通用 provider 插件协议或第二套长期演示应用。内部属性字段组件不新增为公开组件。

仅增加所选区域的实例外观能力与必要局部适配，不改变流程事实源、表单引用、流程设计文档格式、业务校验或宿主存储职责。

### 2. 公开配置书面提案

以下是本规格提交审阅的最小接口提案，不是已经落地的 API；既有决定是行为合同，字段命名与必填约束需随本规格审阅，在实施授权前不视为用户已逐项批准。

两个组件均增加可选的实例配置 prop `appearance`。省略该 prop 表示旧路径；传入合法配置对象显式启用新适配，共用 designer 提供的公开类型。表单包可以复用或重导出该类型，不复制两套合同。

| 配置项        | 提案值与默认                                   | 合同                                                                                                          |
| ------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `colorSource` | `host`／`brand`，省略时 `host`                 | 跟随宿主或显式品牌预设；首批无种子输入与任意 token 覆盖 API                                                   |
| `mode`        | `light`／`dark`，启用时由宿主明确给出          | 跟随宿主时声明宿主当前主题，须与宿主一致；品牌预设时选择实例主题，可与宿主不同。不修改宿主 html/body 启用深色 |
| `density`     | `comfortable`／`compact`，省略时 `comfortable` | 舒适 32px 对应 EP default，紧凑 24px 对应 small；不把日历单元、勾选框等内部几何机械拉成控件高度               |

外观配置的更新不能被当作模型替换、对象选择或表单定义换代。宿主通过公开配置表达主题变化，挂载与配置更新时消费当前宿主主题上下文；任意 CSSOM 修改的通用侦测系统不在本批。

TypeScript 对配置提供约束。JavaScript 调用传入非法枚举或配置对象时，不部分应用非法设置：已有有效配置时保持其呈现，首次配置非法时保持旧路径，并给出含配置项与原因的集成告警；不清空输入，不改业务数据，不伪报业务提交成功。该失败合同同属书面接口提案，取代品牌基线 §6“逐项拒绝并回退默认”的候选规则。

运行中将 `appearance` 从有效配置改为省略，回到旧路径呈现；从省略改为有效配置，进入新适配。两个方向都与外观切换同等保留属性输入缓冲、输入法组合与试填值，不视为模型替换或表单定义换代。这与“有效配置改为非法值时保持上次有效呈现”区分处理。

### 3. 配色来源与局部作用域

跟随宿主时读取宿主 EP 主色、中性色、字体与圆角，为 FlowDuet 自有区域消费或派生需要的可读角色，不写入任何 `--el-*` 变量（含实例范围）；EP 与 FormCreate 控件保持宿主外观，仅由 size 上下文对齐密度。此时 `mode` 只声明宿主当前浅深主题，供 FlowDuet 自有角色选取对应派生值，不能让实例与宿主呈现不同主题；声明与宿主实际主题不一致属于集成配置错误，呈现不在保证范围内，不要求为此建立通用侦测。品牌预设消费批准的 R2 设计值，按实例 `mode` 在实例范围写入映射，仅影响选定区域及其所属弹层，可与宿主主题不同。不得为启用新适配而切换宿主 html/body 主题、重写无关控件、全局白色或宿主通用处理器。

遵守已批准的颜色用途与状态语义；不以辅助色表达错误、警告或待应用，不将样稿中的未实际存在状态新增成业务能力。跟随宿主时 EP 自身继承原值的对比度例外单列，FlowDuet 自有角色仍按批准目标检查。

### 4. 属性抽屉覆盖

使用 `DingtalkDesigner` 既有抽屉路径覆盖审批节点名称、单签审批人或多人审批人集合、四种完成方式、节点表单；抄送名称与收件人；条件分支名称与条件表达式；发起／结束的无可配置字段状态；标题、正文与确定／取消操作。

节点表单保留原生 select 与手写 formKey 两种现有路径，不换成 ElSelect。原生系统选项的可控外观限制据真实浏览器登记，不为像素一致性替换控件。保持既有缓冲、确定／取消、未完成输入法组合的提交保护与错误通道。

抽屉外流程默认表单选择器、节点卡片、分支块、连接线和画布仅作为入口与回归环境，不列入换肤。保持 `propertyEditing` 既有合同，不将外置属性编辑模式变成新的固定面板交付。`propertyEditing="external"` 时不渲染抽屉，`appearance` 可合法传入但本批没有可见效果，宿主自有属性面板也不受其影响；这属于预期，不计为缺陷。

### 5. 表单预览覆盖

`FormPreview` 使用真实 FormCreate 渲染器，覆盖当前文本、多行文本、数字、单选、多选、下拉单选、日期和开关。多行文本继续使用 input 规则的 textarea 形态；日期覆盖当前 date、datetime、week、month、year 单值形态及可达时间子面板，不增加范围或多值形态。

包括表面、标签、必填与错误、项目自有反馈、试填值展示、自有操作按钮以及实际出现的下拉／日期／时间弹层。禁用、清空、空选项、数值与日期边界、校验回调和拒绝处理沿用现有语义，不新增只读模式或字段能力。

### 6. 配置优先级与内容保真

既有表单、字段和栅格的显式 size、标签位置／宽度、inline、style 等值优先，新适配只补默认。不得删除、改写、静默忽略这些值，不用强制 CSS 压过用户业务布局。显式配置造成偏离样稿的呈现允许存在；造成对比或布局问题时列为配置影响，不计作主题目标通过。

启用新适配后，FormPreview 自有操作按钮从写死 small 改为跟随密度；这与用户表单显式 size 分开处理。未启用时保留该按钮旧尺寸，FormManager／FormDesigner 的工具条不动。

### 7. 输入生命周期

切换配色来源、主题或密度时，保留属性输入缓冲、中文输入组合、试填值及有效的当前反馈，不以重建编辑器丢失状态来换肤，不自动确定或取消抽屉。

表单定义替换、切换到另一份表单、同 ID 定义重开时仍按现有合同重置试填状态。外观切换的输入保留不扩展成跨定义保留，也不改变节点对象切换、文档替换或旧模式的业务状态合同。外观不写入 BPMN XML、表单规则／选项、设计文档或保存的试填业务值。

### 8. 弹层、焦点与清理

各区域拥有独立实例作用域与所属弹层。至少支持同一 Vue app 内双实例不同配色来源、不同密度并存，以及品牌预设实例与宿主或另一实例主题不同，内容与遮罩（如存在）均按实际所有者处理。

实例归属在渲染期为弹层追加实例标识，不写回表单规则。规则已有的 `popperClass` 等类名与实例标识合并，不互相替换；规则显式设置 `teleported`、`appendTo` 等改变挂载位置的值时以用户配置为准，由此导致的归属偏差记为配置影响，不计作主题通过。真实弹层在打开、切换、关闭、滚动、缩放和容器边缘应保持主题继承、可操作位置与正确层级。

切换外观时保留当前操作焦点与输入；关闭后按原有交互恢复焦点。卸载／重挂不能残留弹层、实例样式或本次新增的监听资源，不能删除或覆盖宿主处理器。不引入 FormManager 的服务式确认弹层或 FormCreate 设计器内部弹层矩阵。

### 9. 版本、依赖与发布合同

首批源码核对组合为 EP 2.14.6、FormCreate renderer 3.3.4；FormCreate designer 3.5.0 仍为既有依赖但其外壳不在本批。需对真实消费时解析出的组合记录证据，不能仅凭主工作区版本声明兼容。

designer 以 dependencies 声明 `element-plus ^2.14.6`，form-create 的 peer 为 `^2.11.1`；宿主使用 2.11–2.13 时可能解析出两份 EP。首批只验证单份 EP 2.14.6，接入说明将其他组合标为未验证。实现不得依赖跨 EP 副本才能成立的注入上下文（如由 designer 的 EP 副本向 FormPreview 提供 size 上下文）。

不新增或升级依赖、不修改第三方包、不缩窄现有 peer 范围来掩盖未验证。版本绑定覆盖集中在适配职责中，登记目标版本和原因，不散落到业务字段。将来实施按实际公开包变更提供 changeset、接入说明及边界说明；本规格发布不授权发包。
