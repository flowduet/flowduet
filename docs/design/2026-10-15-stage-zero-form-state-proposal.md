## 1. 目的与授权边界

解决 B03：当实施顾问编辑表单的字段默认值、选项或布局，输入仍在控件内部、焦点未离开、拖拽未结束，或导出/恢复失败时，证明切换表单及阶段不会丢输入、串对象、写旧值或误报保存。

本轮用户要求是整理本方案和执行计划供审阅。后续批准 C 组后，优先只扩展隔离探针与测试；不实施正式工作台，不改三包生产源码、根导出、依赖、lockfile、文档编码或部署守卫，不推进 D/E，不推送或发包。发现必须增加产品接缝时，提交失败证据和最小接口差异，另行确认后才实施。

保持 A/B 的身份、租约、冲突与候选隔离合同；只提议§8列出的probe内部只读候选复验入口，不改变已有提交/保存行为。不另建一套可写 session，不按 formId 猜测新对象，不自动合并、覆盖或提交输入。未知替换保留旧实例和冲突输入，存在待确认输入时保存与“当前通过”继续被阻断。

本方案建议沿用“本会话逐片实施，末尾一次独立复核”；该执行方式与本方案仍需维护者确认。不设日历时间盒，失败或成本扩大先报告，不自动减少已确认范围。

## 3. 保真判定与状态层次

一次观察同时记录以下五层，不能仅看成功提示或导出 JSON：

1. **身份**：controllerId/documentEpoch/kind/id/lifetime/facet、EditorLease、视图实例标识；受控改名允许续期，未知替换必须换生命期。
2. **设计语义**：字段标识、类型、标题、默认值及其是否存在、必填、选项值类型与顺序、布局层级与顺序、表单 options。0、false、空串、显式空多选 `[]`、未设置分别断言，不用 truthy 判断或 JSON.stringify(undefined) 抹平差别。
3. **内部输入**：尚未失焦的文字、可实际输入的数字/日期中间串、选项表格未提交单元格、未确认弹窗、composition 状态、拖拽阶段。
4. **编辑上下文**：当前选中字段/配置页、未确认编辑层及适用文本选区。切换按钮自然获得焦点不要求 activeElement 恒等；返回时须能看到并继续该输入，隐藏实例不得抢焦点。滚动位置另记录，不用其替代输入保真。
5. **副作用**：当前 model/session 内容与对象引用、缓冲状态/版本、校验与保存覆盖、宿主 persist 调用、事件次数、另一表单与另一控制器的状态。

导航允许保留内部输入而没有安全快照；这时仍是 dirty/待捕获，不能假装“已保存”。捕获允许合法收集设计草稿，不擅自放宽非法 schema/重复 field 等格式守卫。预览试填值始终不回写设计默认值。

## 4. 字段矩阵

每行均覆盖：从真实菜单创建或装载既有定义 → 改标题/字段标识/必填 → 编辑默认值 → 留在焦点或未确认状态 → A→B→A/表单→流程→表单 → 收集或明确拒绝 → 检查五层状态。适用的清空与恢复再各走一次。下面的示例值固定进入夹具，表单 B 使用不同 field/title/options，避免同名值造成假通过。

| ID / 字段            | 值与清空边界                                                     | 焦点/特有内部状态                                                    | 必查结果                                                                     |
| -------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| F01 文本 input       | 未设置、`""`、`"事项甲"`、`"中文末尾未失焦"`                     | 默认值/标题/field 中正在输入；适用选区；中文组合输入                 | 最新文字及字段归属保留；空串不被改写为未设置                                 |
| F02 多行 textarea    | 未设置、空串、`"第一行\n第二行"`                                 | 连续换行、长中文、composition、未失焦文本                            | input + textarea 形态、换行及文本完整；不得变成单行字段                      |
| F03 数字 inputNumber | 未设置、0、-2、1.5、清空                                         | 原生控件若允许输入 `-`/`1.` 等中间串，逐项记录；输入被控件拒绝也留证 | 0 仍为 number；中间输入未安全提交前不得被重建成旧数值或空值                  |
| F04 单选 radio       | 未设置、数值0、字符串`"0"`、`"normal"`、清空                     | 默认值选择器、静态选项 label/value 单元格、选项增删排序              | 选项与默认值类型不混淆；不偷偷选择首项；待提交单元格保留                     |
| F05 多选 checkbox    | 未设置、显式[]、[0]、["gz","sz"]；清空选择；关闭“设置默认值”     | 默认选项多选层及选项表格                                             | []与未设置可往返；关闭默认值确实未设置；提供者编辑标记不泄漏到文档           |
| F06 下拉单选 select  | 未设置、数值0、字符串`"0"`、`"dev"`、清空                        | 展开的默认值弹层、选项表格、适用过滤输入                             | 保留单选与类型；不出现 allowCreate/multiple/remote；弹层值不串表单           |
| F07 日期 datePicker  | 未设置、清空、`"2026-10-15"`                                     | 日历选中但未完成确认、控件允许的日期输入中间串、失焦格式化           | 实际候选与可见值一致，已输入日期不被静默替换为旧值；未完成状态不得假快照成功 |
| F08 开关 switch      | 未设置、false、true、清空默认值选择器                            | 真实配置中的默认值选择器与其弹层                                     | false不能被当未设置或true；打开/清空后下一次编辑不复活旧值                   |
| L01 栅格 fcRow/col   | 顶层行、两列，字段次序与列归属；无嵌套行                         | 行/列选中、列内字段插入与移动                                        | 容器和字段顺序准确，禁止嵌套 fcRow 的既有规则保持                            |
| I01 日期导入兼容     | props.type省略、date、datetime、week、month、year 的合法单值定义 | 导入→选中→切换→导出；对当前实际开放的配置再编辑                      | 类型与值保留或有明确失败证据；不新增 UI 日期形态，不静默截断时间/月/周信息   |

radio/checkbox/select 的选项统一增加：编辑 label 与 value、增加、删除当前默认选项、移动顺序、value 的 number/string 区分；记录提供者实际清空/悬空行为，不能自行替其归一。删除默认选项后若不能形成合法候选，保留编辑输入并明确拒绝，不假设自动选中其他项。

**矩阵展开规则：** F01–F08 各在顶层及 fcRow/col 内执行；L01和I01按其实际布局/类型枚举。每项在保持挂载、验证后重建两策略下观察。字段通用状态与上表特有状态逐行登记；没有选项的字段，其“选项编辑”列记不适用并引用入口证据。是否可输入中间串、是否存在过滤/确认层在 C0 冻结清单，不能因工具操作失败而标不适用。后续不得只选最容易的字段宣布整列通过。

## 6. 异常与恢复矩阵

此处ERR编号是C组异常用例，不是E组资源工作。每项均在A/B同时有未提交输入的条件下执行；分开作用于第一/第二个捕获对象，验证不是只保留第一个成功结果。探针把异常分层标记，不能覆盖真实FormCreate正常路径的序列化方法来获得“通过”。

| ID    | 故障来源                                                                     | 预期与恢复路径                                                                                                                     |
| ----- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| ERR01 | 适配器flush/capture主动throw；导出返回null                                   | 返回capture-failed，整份候选/保存失败，persist=0；所有实例/输入保留，清除故障后重试捕获到最新输入                                  |
| ERR02 | 适配器返回非法JSON、wrong kind、重复field、范围外规则、options非对象         | 使用现有类型/格式守卫拒绝，保留原输入；不截断/过滤后成功。协议wrong kind与业务非法分开保留错误分类                                 |
| ERR03 | 导出后源验证/目标恢复实例装载throw、未就绪null、回捕获不等价、输入上下文缺失 | provisional实例不成为活跃租约，不写session；保留旧实例并转保持挂载，记录重建失败，不报单实例保真通过                               |
| ERR04 | 旧失败/旧回调晚于新成功，新租约替换后旧实例卸载                              | A/B身份/租约屏障拒绝迟到写入；新输入/新覆盖不被旧失败清空，旧release不注销新租约                                                   |
| ERR05 | 同一时序中的真实第三方自然失败                                               | 不改方法、不加故障开关，在支持UI动作中重现。记录真实堆栈、版本、最小动作；验证失败后保留输入和可恢复性，并纳入永久回归             |
| ERR06 | 用户修正真实非法/未完成输入后重试；或明确选择restore/restart/discard         | 重试以当前完整输入为准，不沿用旧成功章；显式丢弃只影响选中目标/旧比较，另一表单不变                                                |
| ERR07 | 租约已移交后adopt/show或旧实例unmount抛错                                    | 不向失效旧租约回滚，保留新输入/新租约及现存旧比较；重试显示/清理可恢复，迟到旧事件仍拒绝。结果标失败，未确认清理不宣称全部资源释放 |

人工注入ERR01–ERR04/ERR07证明失败处理合同，不是ERR05的替代。文档导入拒绝、故意给库塞BigInt/循环对象、模拟抛错也不能冒充“支持UI自然产生的第三方失败”。若安全的自然失败无法重现，记录已探索的合法状态、真实结果和“自然失败未验证”，B03保持阻断；不为了凑失败破坏用户环境或改依赖。OS输入法无法操作、拖拽工具不支持也同样单列未验证，不用模拟事件补成原生通过。

## 7. 保持挂载与重建策略

| 路径          | 做法与收益                                                                              | 风险及 C 组裁定                                                                               |
| ------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| K：保持挂载   | 复用A/B按完整target/生命期的视图；切换只隐藏，保留原实例、内部输入及租约                | 是保真参照，不是已证明无损；blur、弹层归属和组件内部归一化仍须实测。资源/默认策略由E审阅      |
| R：验证后重建 | 有安全快照且可恢复时，在临时实例装载成对rules/options并比对语义与必要上下文，再接管租约 | JSON相等不足以销毁旧实例；只要不可捕获、组合/拖拽未完成、上下文不可恢复或发生竞态，就不能重建 |
| R的安全回退   | 重建无法证明时保留旧实例，按K完成导航；记录kept-fallback及原因                          | 不强迫用户丢弃再切换，不自动写session；同时存在多个实例是预期回退，不能计入“单实例重建通过”   |

推荐 K 为 C 组参照，R 仅是对照候选。C 不选择正式默认策略、缓存容量、淘汰机制或资源阈值；即使R在部分字段通过，也不得推广到未覆盖状态。

R是“导航时暂停源表单、恢复目标表单”的实验，不是把A内容装进B，也不是换一个A实例后仍全量保持挂载。两策略使用相同初始夹具及动作，但从独立新会话起跑；不能通过中途切换模式清空输入。纯R且没有冲突/回退保留实例时，稳定状态只保留一个可交互编辑器；临时验证峰值可多于一个，不能据此声称资源预算通过。

R的移交顺序必须是：

1. 先确认源A/目标B的完整身份、有效租约、输入版本和最新导航请求；目标若已有必须保留的活实例，优先复用而不是覆盖。源处于composition/拖拽或所有者不明，直接保留，不强行flush。为B显示字段前通过现有openEditor锁定其当前基线，这一步在prepare之前完成，不能等B首次输入才采基础。
2. 原实例仍活跃时调用controller.prepare("draft-save")走已有全对象捕获/隔离屏障；从通过候选对应的源form-content缓冲取成对快照。其他表单非法导致准备失败也回退K，不绕过为只抓当前表单。将内容、原观察上下文及完整target存为会话内待暂停快照，不写session/文档、不复用旧租约。
3. 在不注册活跃租约的临时源A实例中验证该快照可恢复，核对语义、原始value存在性与必要上下文；与捕获前观察比较，不能把blur丢失的输入当成已恢复。清理该验证实例，原A仍在；失败则保留原A。此验证不是最终目的表单。
4. 用B的当前未应用缓冲/有效暂停快照，或从未编辑过时的当前模型定义，准备临时B；恢复其已记录上下文并核对。临时实例的事件不stage/touch，恢复只用现有公开/UI能力，不能写私有字段。旧快照的target失效就按A/B保留冲突，不套同ID新对象。
5. 完成待处理Vue事件后，用拟新增checkPreparedCandidate复验候选，再核对源/目标、上下文和导航请求。检查到registerEditor为B签新租约、releaseEditor撤销A旧租约的同步段内，无await、无宿主回调；源快照留在probe缓存及A/B未应用缓冲中。随后宿主持有B实例并显示B，再卸载旧A；旧A回调/release不能影响B，未来恢复A必须签新租约。
6. 移交前任一步失败/取消先清理临时实例，原实例继续保留；B仍可装载时按K导航并记kept-fallback。B本身无法装载或目标已失效则明确失败并保留A，不伪造导航成功。移交后若adopt/show/旧A清理失败，保留新B/新租约及仍存活的旧比较，不回滚到失效旧租约；报告失败并提供重试显示/清理，不能记为正常切换成功。

K的纯隐藏/显示不作为业务编辑；R租约更换后的校验/保存覆盖按现有A/B规则核对，不能把一次成功捕获或重建当成持久化确认/自动保留校验章。暂停快照以完整targetKey保存，携带内容与上下文，不能成为另一份可写模型事实源。未知替换、删除重建、dispose仍走A/B身份失效；旧快照只能作为旧输入比较，不恢复到新生命期。K回退允许保留多个实例，计数必须如实记录，不再宣称该轨迹维持单实例。

显式restore/restart/discard按既有合同有意放弃输入，必须走其原有确认/比较路径；不套用上述无损导航证明，也不能借显式restore偷做导航清理。

## 8. 接口、文件与生产边界

现有接口原样复用：`createContext(session, owner)`、`createContractController(context)`；`EditorAdapter = { flush(): void; capture(): DraftValue | null }`；`FormDesigner.exportContent()`；store的`registerEditor(target, adapter)`/`releaseEditor(lease)`；controller的`prepare("draft-save" | "validate")`、`apply(target)`、`restore(target)`及既有保存/冲突入口。

当前controller把候选的WeakMap签发记录与完整stamp复验留在内部，R不能仅按公开revision或JSON相等代替。**本方案显式提议**在私有`contracts/controller.ts`增加`checkPreparedCandidate(candidate: PreparedCandidate): EditResult<void>`，抽取复用现有`!disposed && candidates.get(candidate) === stamp()`判定（供原versions与新入口共用）。外来/伪造/过期候选拒绝，dispose返回cancelled，未知读取异常沿用protect；不重新捕获、不改model/session、不提交、不清理较新成功。此入口不进三包根导出。若维护者不批准该最小probe接缝，R不进入实施；K和矩阵调查可保留，不能绕过屏障卸载旧实例。

候选新文件仅位于`apps/playground/probes/stage-zero/`：

- `form-state/fixtures.ts`：八字段、0/false/[]、列布局与日期兼容夹具，复用现有rulesFor并添加有名变体，不复制业务schema守卫。
- `form-state/types.ts`与`state-evidence.ts`：矩阵行标识、五层观察、来源/策略/结果；只读观察不能先exportContent而改变待测状态。
- `form-state/retention-policy.ts`：调用上述只读gate验证候选后再移交租约与K回退；调用A/B，不复制其版本、冲突或候选事务实现。
- `FormStateProbe.vue`：真实组件与C组实验操作；从`ProbeApp.vue`加独立入口，不扩写/复制700行的`ContractInstanceProbe.vue`。
- `form-state.test.ts`、`form-state/retention-policy.test.ts`、`editor-recovery.test.ts`：语义/状态观察、时序与失败回归。

调查和探针允许观察可定位DOM及上游公开接口，不fork、不启用Pro、不改第三方私有状态，不新增全局快捷键/全局blur或CSS。需要生产`FormDesigner`的新公开方法/事件、异步flush签名、上游依赖升级、超出上述gate的controller调整或A/B公共合同变化时，在该片停下；先给出复现与准确接口提案，不能由C批准自动扩大白名单。
