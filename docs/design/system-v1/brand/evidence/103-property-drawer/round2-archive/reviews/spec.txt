1. **[细节] 公开文档与验收记录将“系统色关键字”归入“仍使用既有默认值”，与离屏 `<canvas>` 实际求值行为不符**
   - **位置**：
     - `packages/designer/README.md:105`
     - `docs/design/system-v1/brand/103-property-drawer-verification.md:110`（增量补丁末节第 4 条）
   - **触发条件**：宿主在自定义 `--el-*` 变量中使用 CSS 系统色关键字（如 `CanvasText`、`ButtonFace`），尤其在 `mode: "dark"`（即使 `document.documentElement.style.colorScheme = "dark"`）下启用 `colorSource: "host"`。
   - **代码与实测证据**：`packages/designer/src/appearance-style.ts:415-436` 的 `readBrowserColor` 使用未挂入文档树的离屏 `<canvas>` 2D 上下文解析颜色。以本机同一 Headless Chromium 156 实测：
     - `light-dark(#112233, #ddeeff)` 与非法颜色确实被 `context.fillStyle` 拒绝（双哨兵比对抛错），回退到 `HOST_DEFAULTS[mode]`（既有默认值）；
     - 但 `CanvasText`、`ButtonFace` 等合法系统色关键字**不会被 `context.fillStyle` 拒绝**，而是按未挂树画布固定的浅色 `color-scheme` 直接求值为 `#000000`、`#EFEFEF`（即使根元素已设 `color-scheme: dark`），**不会进入 `catch` 回退 `HOST_DEFAULTS`**。
   - **处置建议**：无需扩大产品代码范围，仅将 `README.md:105` 与 `103-property-drawer-verification.md:110` 文案拆清即可（例如改为：“不支持依赖宿主 `color-scheme` 的 `light-dark()` 与系统色关键字；非法颜色仍使用既有默认值”）。
