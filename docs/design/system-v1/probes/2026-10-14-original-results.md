## 验证与证据范围

执行前，既有 428 个测试通过。最终按 `pnpm -r --no-bail test` 复跑全部包：core 125 通过；designer 141 通过、7 项已知结构合同失败；form-create 121 通过；Playground 64 通过。合计 **451 通过、7 失败**，不是全绿。新增入口开关在第一次实现中触发了 Vue 可选布尔属性的缺省 false，旧测试捕获后已设显式默认 true；修复前日志保留，修复后的原有回归恢复通过。

常规 `pnpm build` 通过，保留现有大 chunk 警告；它不包含临时探针页面，所以不能代替探针类型检查。探针 lint 和格式单独检查。临时 tsconfig 引入现有 moddle 声明后，仍保留 EP Select/Option 的模板类型错误，没有用 any/禁用检查掩盖。

浏览器使用 Codex in-app browser；页面通过 Vite 源码别名加载真实组件，测试数据均为虚构样例。样例、控件与探针在开发过程中分轮验证；热更新曾保留旧 props 状态，最终默认入口结论在 `a293b24` 上完整 reload 后复验，见 [最终入口记录](evidence/default-form-entry-final.json)。其他中间截图仅用于其对应的局部观察，不冒充最终设计视觉验收。环境和版本见 [manifest](evidence/manifest.json)。

这是一组阶段零探索样例，不是完整功能矩阵：尚未穷尽全部属性弹层、长文本/固定面板三档宽度、真实路由卸载、全部未序列化状态及外部原位模型变更。Performance/Memory CDP 指标不可用，未获得堆内存或监听器数量，未得出内存泄漏结论。

[独立复核](independent-review.md) 未发现新的 Critical/Important。保留两项日志限制：documentEpoch 固定为 1，不能证明跨文档请求归属；“已定位”文字/located 事件只表示点击派发，必须另查真实 UI 状态。既有结论以控制器测试与状态面板为准。

## 如何复现探针

在本分支的仓库根目录：

```sh
pnpm --filter @flowduet/playground exec vite --config probes/stage-zero/vite.config.ts --host 127.0.0.1
```

打开返回端口的 `/probes/stage-zero/index.html`。编辑保留、主题隔离、宿主协议三个入口分别提供真实组件样例。保存适配器只在内存中由人工确认成功/失败，不写业务存储。
