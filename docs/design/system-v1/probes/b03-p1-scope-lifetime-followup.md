## 复审问题及修复

上轮四文件补丁后，原App与定位文件已有hook关闭与局部target保护，但新增工具回归文件未纳入同等用例生命期。两轴复审确认同一P2：Vitest默认超时先执行afterEach，异步测试体不会自动取消；局部scope仍活动，晚到finally首次close会清除B的DOM/storage/spy与兼容描述符。旧的6/6只验证显式关闭A再打开B，没有覆盖runner先结束用例的路径；上轮851/851是真实实跑，但不能代替这一交错。

临时副本按真实默认5秒复现了A超时、B挂载与建spy、释放A旧finally：B connected/spy均true→false，结果为A预期timeout和B断言失败两项。仅等一次flush的首轮没有命中，后来用完成门固定A finally与B观察的先后，属于受控协议，不追认历史失败的唯一因果。

本轮改动仅两份测试侧源码：

- `browser-test-scope.ts`追加私有`createBrowserTestCase`。用例所有者创建并登记每个scope的卸载/清理闭包；结束时先使所有者失效，再按安装逆序关闭全部scope。即使一个卸载抛错也继续其他scope，随后保留错误；重复结束无操作。失效后拒绝续体与创建新scope，原Element/Storage兼容工具逐字不变。
- `browser-test-scope.test.ts`登记每例及多对象夹具，afterEach调用共享结束函数，finally兜底恢复全局。async体捕获本例owner，await之后核验，不能晚到读取新的currentCase。旧finally只关闭本例已登记的scope，在hook已经结束后幂等跳过。A/B用例在创建B兼容层前同样核验本例，避免只保护旧target却容许旧续体新建scope的漏洞。

新增3项正式回归：同例模拟用例A结束→真实B开始→释放A旧续体/finally，核对B连接、抽屉、输入、spy身份/调用次数、storage内容/方法、Element描述符及真正配置审批人后的保存模型；同时拒绝旧A再开scope。另两项使用真实双App，验证正常/真实卸载后注入异常均逆序关闭全部scope、恢复描述符、保留错误且不重复卸载。模拟结束复用afterEach的同一关闭函数，不将实际timeout失败留在正式CI中。

旧helper32处expect表达式与原标题保留、原App/定位文件字节不变，原252处业务断言与输入/时限沿用。没有产品包、App.vue、依赖/lockfile、CI、worker或测试全局配置变动；默认5秒与原已有15秒选项均保持。
