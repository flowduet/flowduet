# FlowDuet 品牌与体验重设计讨论

- 日期：2026-10-14。
- 状态：整体方案已通过复审；补充合同和阶段零计划待审阅。下列编号条目为此前用户已确认选择，本轮补充建议另列，不混作全部实现完成。
- 本文记录 grill-with-docs 讨论，不替代实施规格或实施授权。

## 已确认的目标与范围

1. 首要目标是统一现有产品体验：双视图、属性面板、表单设计看起来和用起来属于同一套产品。宿主定制范围由第 7、11 项确定；官网等对外物料不属于当前已确认范围。
2. 深度为全面体验重设计，包含页面结构、操作路径、面板布局和功能入口；不限于视觉皮肤或基础交互规范。
3. 主要操作者是流程实施顾问：熟悉流程建模，重视效率、较高信息密度和精确配置。发生体验取舍时优先考虑该人群。
4. 优先打磨从零完成一套流程的路径：建流程、配置节点与条件、设计并绑定表单、校验并交付。复杂流程修改与问题排查尚未细化优先级。
5. 主路径按完整体验设计；发现功能缺口后逐项提交用户确认，再决定是否实施。校验定位已在第 14 项单独确认；BPMN 编辑、撤销重做等未获纳入。
6. npm 交付同时提供可嵌入的完整设计界面与可单独组合的组件；宿主负责存储和发布。完整体验需可复用，不能仅存在于 Playground。分包方向见第 15 项和 [ADR-0010](../adr/0010-integrated-designer-delivery.md)，具体接口待书面方案审阅。
7. 首期同时交付浅色与深色主题，并支持宿主定制，项目见第 11 项。
8. 整体工作方式采用阶段式工作台：以基本信息、表单、流程、校验交付组织任务，允许跨阶段跳转，不采用必须逐步通过的顺序向导；布局见第 9 项。
9. 布局采用顶部阶段导航与固定属性面板（布局原型方案 A）。后续基于此布局细化；不采用左侧阶段导航或按需属性抽屉作为默认布局。
10. 默认视觉采用“双色品牌”方向（视觉原型方案 C）：延续既有标志，靛蓝为主、珊瑚橙少量点缀，建立明确品牌识别。原型中的具体颜色、尺寸和对比度尚未定为正式规范。
11. 宿主可定制主色、辅助色、字体、基础字号和圆角，并配置紧凑/舒适密度、属性面板宽度。尺寸边界和具体接口待设计；该选择不代表已决定提供终端用户拖拽面板宽度等新交互。
12. 首期完整编辑体验以桌面为目标，覆盖常见笔记本及桌面宿主；暂不承诺平板或手机完整编辑。适配依据为嵌入容器宽度，最小可用宽度由真实样稿验证确定。
13. 跨阶段直接切换，保留尚未完成的输入与编辑上下文，返回可继续编辑；明确显示未保存状态。会话内保留不等于持久化保存，交付仍执行完整校验。具体缓冲与恢复机制待设计。
14. 首期新增集中校验与问题定位：覆盖现有校验已识别的配置问题，切换到对应阶段并定位节点、分支或流程默认表单配置。无法确定位置的错误显示原因，不猜测跳转；不承诺第三方表单设计器内部全部字段错误的定位。
15. 初次确认按“设计规范与关键页面稿 → 真实组件适配验证 → 工作台与组件落地”推进，后经第 19 项在前面增加技术探针。沿用现有三包职责：公共主题与流程组件放在 designer，完整流程与表单装配放在 form-create，core 保持无 UI 依赖；基础控件复用现有库。当前授权为提案整理与修订，代码探针及产品代码尚未进入实施。
16. 审核反馈后的流程身份边界：新建时填写或由宿主提供流程 ID 与名称；创建后 ID 只读、名称可修改。宿主检查部署范围内的 ID 冲突；合法性校验及名称修改合同在实施前明确，不引入已有流程改 ID 的能力。
17. 固定属性面板按对象保留输入缓冲，提供“应用/还原”。切换对象不自动提交或丢弃；保存整份草稿时统一收集缓冲，无法合法收集时明确报错并保留输入。跨阶段输入保留规则继续有效。
18. BPMN 视图维持当前只读且无对象选择的边界，属性区展示流程级只读摘要；问题定位至可编辑对象时切回钉钉式视图。不增加 BPMN 对象选择、高亮或在该视图编辑属性的能力。
19. 审核后调整交付顺序：技术探针前置于完整页面稿定稿，保留既定范围，不预先接受表单设计器浅色孤岛或第三方隔离降级。验证失败后依据证据逐项决定调整或延期；本次调整不等于已授权启动代码探针。
20. 不设日历时间盒，以阶段成果与复审控制推进；出现成本扩大或验证无法收敛时重新决策，不自动扩大投入，也不自动削减既定范围。不虚构整轮工期或 v1 延期天数。

## 现有约束与代码事实

- [ADR-0008](../adr/0008-logo-visual-identity.md) 已接受“一树两冠”标志及靛蓝 `#2D3E97` / 珊瑚橙 `#F76547`；本轮已确认延续该品牌基础，采用第 10 项视觉方向。
- [ADR-0001](../adr/0001-project-positioning.md) 将真实集成使用作为价值标准；设计需考虑 npm 组件集成场景。
- [ADR-0002](../adr/0002-bpmn-xml-source-of-truth.md) 与 [ADR-0003](../adr/0003-dual-view-architecture.md) 约定共享模型事实源及双视图投影关系。
- [现有视觉方向](../assets/design/iteration-2/README.md) 是方向稿，不是完整像素规格。
- 当前自有组件与 Element Plus、FormCreate、Vue Flow 共同构成界面；源码中存在分散的硬编码颜色、尺寸等样式值。本次源码检索未发现统一公共主题接口，不据此判断第三方库自身的主题能力。
- 当前 `BpmnCanvas` 是只读投影；全面重设计不自动表示已经决定增加 BPMN 编辑能力。
