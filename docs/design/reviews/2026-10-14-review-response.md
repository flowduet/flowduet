## 结论

初稿确有属性容器与既有 ADR 的冲突未说明、固定面板提交与对象切换规则缺失、流程身份路径不完整、关键技术验证过晚、宿主协议和工作台状态归属不足等问题。应先修订合同并前置探针，不能直接冻结完整高保真页面稿或开始大范围实施。

报告中的风险判断不能全部作为已经复现的失败。尤其是第三方隔离能否实现、全局注册的实际影响与内存代价，均需真实组件证据；新增依赖、改变 peer 声明和削减主题范围也不因报告建议自动获得授权。

## 用户已重新确认的五项决定

1. 新建时确定流程 ID 与名称，创建后 ID 只读、名称可改；宿主检查部署范围内的 ID 冲突。
2. 固定面板按对象保存输入缓冲，提供应用/还原；对象切换不自动应用，整份草稿保存时统一收集。
3. BPMN 视图展示流程级只读摘要；问题定位回到可编辑界面，不新增 BPMN 对象选择与高亮。
4. 技术探针前置；保留已经确认的范围，不预先接受浅色表单区域或第三方隔离降级。
5. 不设日历时间盒，以阶段成果和复审控制推进；成本扩大时重新决策，没有自动砍序或虚构的 v1 延期日期。

## 关键证据与纠偏

### 流程身份风险成立，但不要求首期实现改 ID

[`FlowDesignSession.newDesign`](../../../packages/form-create/src/session.ts) 接受 `processId`/`processName`，默认值为 `flow_1`/`未命名流程`；当前 Playground 无参调用它。core 创建时只检查 ID 非空，因此新建身份合同仍需补充合法性范围。

Flowable 使用 BPMN process 的 ID 作为 process definition key，同 key 的后续部署递增版本；部署作用域内的碰撞风险需要宿主处理。[Flowable 官方部署说明](https://www.flowable.com/open-source/docs/bpmn/ch06-Deployment)

“取消基本信息阶段”本身也不会解决默认 key 重复，必须同时定义身份来源。本轮用户已经选择在新建环节处理身份。

### 弹层隔离需按实际入口验证

已安装 Element Plus 2.14.6 的 dialog props 中 `appendToBody` 为 Boolean，未设时为 false；drawer 的 teleport 条件为 `appendTo !== 'body' ? false : !appendToBody`。当前 `NodeDrawer` 没有显式启用 `appendToBody`，所以不能将它当作“默认挂 body”的证据。

已安装 FormCreate Designer 3.5.0 源码中，部分 Struct、FnInput、预览等对话框显式使用 `append-to-body`；但项目配置关闭了不少高级入口，需要确定实际开放功能可达的弹层再验证。这个事实支持“有隔离风险”，不支持“必然无法实现”。

Element Plus 官方暗色入口通过 `html.dark` 启用，也支持变量/SCSS 定制；实例主题不能直接照搬全局入口。具体作用域与弹层桥接需验证，不将官方示例当作只能修改 html 的排他性限制。[官方暗色主题说明](https://element-plus.org/en-US/guide/dark-mode.html)

[`ensureFormCreateInstalled`](../../../packages/form-create/src/form-create-setup.ts) 会向当前 Vue app 注册插件与组件。这是 app 级注册影响，需要单独检查兼容性；它不是与 CSS 全局导入相同的一种副作用。

### 状态迁移和测试范围

[`App.vue`](../../../apps/playground/src/App.vue) 的编辑世代、保存/打开序号、缓冲收集及 Cmd+S 监听确实还在 Playground；[`FlowDesignSession`](../../../packages/form-create/src/session.ts) 刻意保持框架中立。迁移方案须保持其职责边界并锁定现有竞态合同。

本轮完成的是源码/文档复核和提案修订，没有做真实浏览器主题、弹层、内存、跨对象缓冲或引擎部署验证。因此上述风险仍列为阶段零的验证对象，不能在复核记录中关闭为“已修复”。
