## 版本、配置与生成文件

- `branch-identity-preservation` 的 core 分类从 patch 改为 minor，理由为新增公开 `BpmnModel.retargetSequenceFlow`，这是用户已选方案；designer 对应 patch 保持。
- 顶层无效 `updateInternalDependents: always` 移至当前工具支持的 `___experimentalUnsafeOptions_WILL_CHANGE_IN_PATCH`。实际 `readConfig` 返回 always、warnings=[]；不升级工具依赖，`updateInternalDependencies` 仍为默认 patch。
- `pnpm changeset status` 在版本化前给出三包 0.4.0/0.2.0/0.2.0、十份 Changesets；随后实际执行 `pnpm version-packages`，更新三包 package.json/CHANGELOG，删除已消费十份文件。

- 内部依赖源码仍为 `workspace:*`；实际 tarball 已解析为 D→C 0.4.0、F→C 0.4.0、F→D 0.2.0。Vue/EP/FormCreate 等依赖及 peer 区间未改，锁文件无需修改；`pnpm install --frozen-lockfile --offline` 通过。

版本化后再次调用 `changeset status --output` 返回 1：该 CLI 在工作区存在包变更、但 Changesets 已被 version 消费时提示“Some packages have been changed but no changesets were found”，没有生成空状态报告。本页不将其记为退出 0，也不为消除提示补一份空 Changeset。确认依据为版本化前计划、version 输出、已消费文件、三包版本/CHANGELOG 和实际包 manifest，而不是伪造剩余计划。
