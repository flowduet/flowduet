## 行为与测试入口

`npm run typecheck` 使用同一次 tsc 的诊断与实际文件清单核对三个必验入口，固定公开合同从上轮最终通过的 `release-contracts.ts.txt` 收编。缺文件、漏编译及类型错误均失败。运行合同复用上轮最终成功驱动与临时宿主，新增稳定用例 ID、结果回执、产物绑定及完整性汇总。

回归通过公开 CLI 的输入、退出码和 JSON 报告验证，不调用内部函数。观察红后逐项补实现：类型文件漏编译；实际模板遗漏合同；运行回执缺项；重复、缺结果及缺证据；逐项风险范围；产物字节变化；损坏回执遗留旧成功汇总；风险跨批次误用。合成回执仅证明校验器行为，不当作产品运行证据。

静态 `verification.json` 记录三包 tarball、生产构建哈希和类型实际文件清单。运行驱动核对本地文件及预览服务字节，浏览器实际网络响应也必须核验后才能交付给页面，拒绝未知资源及预检后的服务切换。回执绑定该 verification 原字节 SHA-256；汇总再次核对本地产物。缺项、重复、未知、缺成功证据、全局浏览器错误或哈希不一致均不能完成。明确接受的失败风险仅对指定 ID 和产物批次生效，保留失败反例、理由及授权来源；`complete-with-accepted-risk` 不冒称全部通过，未执行项不能豁免。
