## 1. 支路头语义丢失：现有缺陷已复现

| 操作                                    | 诊断场景                 | 实际结果                                                |
| --------------------------------------- | ------------------------ | ------------------------------------------------------- |
| 单签 → 多人                             | 条件支路、默认支路各一例 | `fa` 变为 `flow_conv_in_1`，名称及原有条件/default 丢失 |
| 多人 → 单签                             | 条件支路、默认支路各一例 | 同上                                                    |
| 删除首节点，支路仍有后继                | 条件支路、默认支路各一例 | `fa` 变为 `flow_relay_1`，名称及原有条件/default 丢失   |
| 删除外层支路开头的嵌套块，后面保留 tail | 条件支路一例             | `fa` 变为 `flow_block_relay_1`，名称及条件丢失          |

这七个结构样例都观察到兄弟支路顺序从 `[fa, fb]` 变成 `[fb, 新连线]`。根因是 `removeNode` 级联删除连线、清除网关 default，视图操作随后只按端点追加新连线。转换注释中的“前后连线原样保留”不符合实际字段与身份行为。

采纳修复目标，并扩充为：存续支路的头连线 ID、完整条件表达式、名称、default 引用和支路顺序必须保留；单↔多转换两侧仍存续连线也不应无故换身份。真正删除的对象必须失效。先比较原位修改与安全重接的实现路径，再单独审阅核心修复；不要只把新连线改回旧 ID 就声称全部字段、引用和顺序已保真。

七个样例不是全部结构操作矩阵，也没有证明 DI 已保留或 XML 真实部署成功。生产修复尚未实施。

## 2. 同文档 ID 复用：最终 ID 差集不足

实际运行 `removeApprovalNode(approval_1)` 后，在另一个保留节点后调用 `insertApprovalAfter`，新节点立即取得 `approval_1`。其元素对象已不同，但操作前后 ID 集合都包含该 ID。用一个模拟缓冲 Map 执行“删除不在最终集合中的 ID”，旧缓冲仍然存活。

因此采纳级联清理要求，但加强为对象生命期合同：删除清理发生在可复用 ID 之前，并覆盖全部级联节点、连线、嵌套块及其选中/诊断引用；同一原子操作里的删除重建也要通过操作意图区分连续转换与新建对象。外部直接改模型时，在应用、保存和定位前校验身份/基础状态，不能只在 UI 删除按钮里清理。

新工作台缓冲尚未实现；已复现的是现有 ID 回收与建议的 ID-only 策略不充分，不是声称已运行一个不存在的新工作台。表单身份也应考虑复用：当前 session 根据目录长度探测 `form_n`，例如删除末尾表单后创建，可重新得到相同字符串 ID。

## 3. 应用、多表单切换与默认入口

- 新工作台“应用”采用显式草稿级 `allowIncomplete: true`，仅放行业务缺项；非空非法格式、结构冲突和不支持的数据仍拒绝。普通抽屉“确定”、未显式启用的默认调用和部署导出维持原合同。需要注意：现有普通确定本来也不是覆盖所有业务规则的完整部署校验。
- 表单阶段按文档和表单生命期保存设计器状态、rules/options 与未序列化输入；切换目录不自动写 session，不丢未应用内容。保存/校验收集全部缓冲；真实编辑器是否需要保留多个挂载实例、资源代价如何，由探针给出证据。
- 工作台内仅表单阶段提供流程默认表单的编辑入口；嵌入流程组件隐藏内置选择条，流程页只显示摘要/跳转。独立组件默认仍按现有 formOptions 显示内置入口。

以上是本轮规格细化，尚未更改 `NodeDrawer`、`FormManager` 或 `DingtalkDesigner`。

## 4. 校验有效期依据候选结果，不依据按钮动作

采纳有效设计状态原则。校验通过绑定“模型 + 表单 + 全部缓冲”的候选结果、文档世代与有效定位身份；原样应用同一候选状态可保留结论，保存状态单独维护。真正改变有效内容的输入、还原或模型/表单修改使结论失效；无变化的重复应用或还原不强制失效。

若应用发生额外规范化、默认补入或有损结构变更，不能凭“点的是应用”就保留通过状态；需要证明结果等价且定位目标仍有效，无法证明时保守重验。第 1 项未修复时，结构转换会真实改变分支语义，绝不能列为等价应用。
